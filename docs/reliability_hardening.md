# 안정성 보완 1차

## 적용 범위

1. 인증 격리: CookieManager를 모듈 전역에 보관하지 않는다. 현재 Streamlit 세션의 한 번의 스크립트 실행에서만 재사용하고 다음 rerun에는 브라우저 쿠키를 다시 읽는다. 쿠키 쓰기는 HTTPS secure, SameSite=Strict를 사용한다.
2. 저장 충돌: 로드한 portfolio_snapshots.updated_at을 기준으로 owner/name/version 조건부 UPDATE를 수행한다. 신규 저장은 INSERT로만 수행한다. 오래된 버전이나 중복 INSERT이면 자동 덮어쓰기를 중지한다.
3. 부분 평가: 가격 없는 종목의 알려진 매입금액은 유지하고 평가액은 미산정으로 남긴다. 손익률은 가격과 원가가 모두 있는 종목만 분자·분모에 사용한다. 합계·비중에 부분 평가를 표시하며 전체 IRR은 산출하지 않는다.
4. 최신성: 공식/쉐도우 산출물은 열린 세션에서도 rerun 때 10분 간격으로 재확인한다. 가격 갱신 버튼은 해당 URL 캐시를 무효화한다. 기존 앱 내부 미리보기 계산은 삭제하지 않고 30분 캐시로 중복 계산을 줄였다.
5. 회귀 검사: 공개 대시보드 렌더러를 합성 데이터로 실행하는 검사와 Python 3.12 CI 검사를 추가했다. 기존 Python 3.11 검사와 job 이름은 유지한다.

## 저장 보호 경계

- RLS와 사용자 access token은 그대로 사용한다. 새 service role key나 DB migration은 필요하지 않다.
- PC와 모바일이 같은 버전을 읽은 뒤 저장하면 첫 저장만 성공한다. 다른 화면에는 충돌 알림, 현재 입력 JSON 백업, 명시적으로 확인한 뒤 최신 저장본을 불러오는 동작을 제공한다.
- 현재 입력을 자동으로 버리지 않으며 같은 충돌 상태에서 매 rerun마다 저장을 재시도하지 않는다.
- `save_portfolio_if_unchanged`가 원자적인 보호 경계이다. 기존 `save_portfolio`는 하위 호환용으로 남았으므로 신규 UI 저장 경로에서 직접 호출하지 않는다.
- 별도 target_allocations 테이블과 자산추이 기록까지 하나의 DB 트랜잭션으로 묶은 것은 아니다. 다중 테이블 원자성은 별도 RPC/마이그레이션 설계가 필요한 후속 작업이다.

## 최신성 표시

- 검증 결과 `signals/latest_validated.json`과 최신 실행 상태 `runs/latest_run.json`을 별도로 확인한다. 실패한 실행이 직전 검증 결과를 최신 성공처럼 보이게 하지 않는다.
- NO_NEW_SESSION과 최근 실행 시각이 있으면 주말·휴일에 판정일이 같아도 정상적으로 유지한다. 마지막 실행 확인이 36시간을 넘으면 이전 검증값임을 알린다.
- 실행/신호 파일이 서로 다른 배포 시점이면 배포 대기로 표시한다. 산출값이나 전략 규칙을 앱에서 임의 보정하지 않는다.
- 사용자 지정 URL이 표준 경로가 아니면 최신 실행 상태 별도 확인 필요로 표시한다.
- 화면을 건드리지 않는 동안 자동 폴링하는 기능은 추가하지 않았다. 재확인은 다음 화면 동작/rerun 또는 가격 갱신 시 수행한다.

## 차트분석 조회

- 종목별 정상 결과는 30분 캐시한다. 공개 탭에 재진입하거나 rerun할 때 세션의 마지막 조회 시각도 검사한다.
- 수동 전체 새로고침은 현재 보유종목 캐시만 무효화한다. 미완료가 있으면 이미 받은 정상 결과를 재사용하며 이어서 조회한다.
- 새 결과가 실패하거나 이전 거래일로 후퇴하면 직전 정상 결과를 보존하고 `이전 정상값 · 재조회 필요`를 표시한다.
- 전체 조회는 24초 경과 이후 새 종목 조회를 시작하지 않는다. KIS 일봉은 12초 경과 이후 새 페이지/거래소 요청을 시작하지 않는다.
- **24초는 강제 종료 제한이 아니다.** 진행 중 HTTP 요청의 timeout, 토큰 대기, 데이터 변환 시간만큼 더 걸릴 수 있다. 미리보기·환율·시세 전체를 합친 응답시간 상한을 보장하지 않는다.
- 대화형 차트분석은 KIS와 timeout이 있는 Yahoo 경로를 사용한다. timeout을 전달할 수 없는 FinanceDataReader fallback은 해당 화면에서 사용하지 않는다. 일반 현재가 조회의 기존 fallback은 변경하지 않았다.

## 검증

- 로컬 Python 3.12 pytest: 539 passed, 기존 exchange_calendars/NumPy deprecation warning 5개. Windows 임시 폴더 권한 및 긴 경로 문제를 피해 짧은 별도 `--basetemp`와 `-p no:cacheprovider`로 재검증했다.
- 시계가 멈추거나 뒤로 이동해도 메모리 저장 버전이 증가하도록 보강하고 동시 저장 회귀 검사를 추가했다.
- 브라우저: 1440/768/390px의 총괄현황·차트분석, 라이트/다크 전환과 탭 유지, 모바일 부분 평가·로그인 화면을 확인했다.
- `tests/browser/smoke.cjs`: 3개 폭, 2개 테마, 탭 유지, 로그인/빈 데이터/부분 평가, 오류 화면, 가로 overflow, HTML 코드 노출 검사와 스크린샷 저장.
- CI에서 browser-regression artifact로 스크린샷과 서버 로그를 남긴다. 로컬 CUA/AppTest 검사에 더해 실제 Playwright 스크립트 전체를 Edge headless에서 실행해 통과했다.
- PR #141의 첫 CI는 테마 변경 중 이전 DOM을 대상으로 스크롤하여 실패했다. 테스트 전용 렌더 완료 표식의 새 실행 번호·테마·탭과 Streamlit의 idle 상태를 함께 기다리도록 수정했다. DOM 분리 오류에만 최대 3회 재탐색하며, 누락된 표·다른 오류·계속되는 분리는 실패로 유지한다. 재시도 helper 단위 검사 3개도 통과했다.
- 선택 패널이 비어 있을 때 총괄현황 뒤쪽 HTML이 Markdown 코드로 표시되는 문제를 브라우저 검사에서 발견하여 수정했다.

로컬 UI fixture:

```bash
python -m streamlit run tests/browser/fixture_app.py --server.port=8591
```

`http://127.0.0.1:8591/?scenario=partial&theme=light`처럼 사용한다. fixture는 운영 계정 인증·DB·시세 API를 대체하며 배포 진입점으로 사용하지 않는다.

CI 구성은 [Playwright 공식 CI 안내](https://playwright.dev/docs/ci)를 참고한다. 실제 Android WebView, 두 실기기의 저장 충돌, 장시간 로그인 복원, Supabase RLS 통합 검증은 배포 전 수동 QA로 남는다.

## 후속 범위

전체 renderer/service 분리, 다중 테이블 원자적 저장, API 회로 차단기·백그라운드 작업 큐, 운영 지표 수집, Android DOM observer 개선은 아직 구현하지 않았다. 이번 단계는 인증 객체 격리, snapshot 충돌 보호, 부분 평가, 캐시 최신성, 조회 요청량, 회귀 테스트에 집중했다.
